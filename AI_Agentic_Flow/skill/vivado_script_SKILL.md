# Vivado Non-Project Mode — Script Generation Skill

Produces a complete, annotated Vivado non-project Tcl build script following AMD/Xilinx
official guidance (UG892, UG835, UG894, UG904, UG896, UG903) and practitioner best practices.

---

## Inputs

- **Part number** (required) — the user must supply the exact Xilinx part string, e.g.
  `xc7k325tffg900-2`, `xcvu9p-flgb2104-2-i`, `xczu7ev-ffvc1156-2-e`
- **Top-level module name** (ask if not given) — the RTL top entity/module name
- **User sources file** (required) — a separate `run_sources.tcl` file that the user maintains;
  the generated script will `source` it to add all RTL, IP, and XDC files
- **Output directory** (default `./out`) — where checkpoints, reports, and bitstream are written
- **Enable ILA / debug probes** (optional, default yes) — include `write_debug_probes` step

---

## Key Design Decisions

### Non-Project vs. Project Mode
In non-project mode, Vivado holds an **in-memory design object** only — no `.xpr` file, no
`runs/` directory, no auto-reruns on file change. Every stage (synth → opt → place → route)
must be **explicitly invoked** and **checkpointed manually**. This makes the flow reproducible,
CI-friendly, and source-control clean.

**Reference:** UG892 §"Non-Project Mode Tcl Script Example"; UG894 §"Batch Scripting"

### Source File Injection via `run_sources.tcl`
Rather than hardcoding file lists in the build script, all `read_vhdl`, `read_verilog`,
`read_ip`, `generate_target`, and `read_xdc` commands live in a **separate user-maintained file**
(`run_sources.tcl`). The build script calls:

```tcl
source run_sources.tcl
```

This keeps the build orchestration script stable while allowing the user to freely add/remove
design sources without touching the flow logic.

### IP Usage (UG896, UG903)
- Always reference IP via the `.xci` file: `read_ip path/to/ip.xci`
- Call `generate_target all [get_ips]` after reading all IPs
- `report_compile_order` after source reading is recommended to catch missing files early
- XDC files for IP clocks must be read in `NORMAL` order after user XDC; set
  `set_property PROCESSING_ORDER LATE [get_files ...]` if needed

## Output Script Structure

Generate the build script **in this exact order**, with inline comments as shown:

```tcl
#==============================================================================
# Vivado Non-Project Mode Build Script
# Part   : <PART_NUMBER>
# Top    : <TOP_MODULE>
# Generated by vivado-non-project skill
# Reference: UG892, UG835, UG894, UG904, UG896, UG903
#==============================================================================

#------------------------------------------------------------------------------
# 0. Configuration
#------------------------------------------------------------------------------
set TOP       "<TOP_MODULE>"
set PART      "<PART_NUMBER>"
set OUTDIR    "./out"

file mkdir $OUTDIR

#------------------------------------------------------------------------------
# 1. Target device
#------------------------------------------------------------------------------
set_part $PART

#------------------------------------------------------------------------------
# 2. Read design sources
#    All read_vhdl / read_verilog / read_ip / read_xdc commands live in
#    run_sources.tcl — maintained by the user separately.
#    Structure of run_sources.tcl should follow the pattern:
#      read_vhdl    ../rtl/top.vhd
#      read_verilog -sv ../rtl/core.sv
#      read_ip      ../ip/fft/fft.xci
#      generate_target all [get_ips]
#      read_xdc     ../xdc/clocks.xdc
#      read_xdc     ../xdc/pins.xdc
#------------------------------------------------------------------------------
source run_sources.tcl

# Sanity check: verify compile order (catches missing/unresolved sources early)
report_compile_order -missing_instances

#------------------------------------------------------------------------------
# 3. Synthesis
#    -top    : top-level module/entity name
#    -part   : must match set_part above
#    UG835: synth_design; UG892 §Synthesis in Non-Project Mode
#------------------------------------------------------------------------------
synth_design -top $TOP -part $PART

write_checkpoint -force ${OUTDIR}/post_synth.dcp
report_utilization      -file ${OUTDIR}/post_synth_util.rpt
report_timing_summary   -file ${OUTDIR}/post_synth_timing.rpt

#------------------------------------------------------------------------------
# 4. Optimization
#    UG904: opt_design must run before place_design in non-project mode
#------------------------------------------------------------------------------
opt_design

#------------------------------------------------------------------------------
# 5. Placement
#    Checkpoint after place is essential for timing analysis and re-entry
#    UG904 §Running Implementation in Non-Project Mode
#------------------------------------------------------------------------------
place_design
write_checkpoint -force ${OUTDIR}/post_place.dcp
report_timing_summary   -file ${OUTDIR}/post_place_timing.rpt

#------------------------------------------------------------------------------
# 6. Physical Optimization (optional but recommended for timing closure)
#    Remove or comment out if design closes timing after place_design
#------------------------------------------------------------------------------
phys_opt_design

#------------------------------------------------------------------------------
# 7. Routing
#    UG904: route_design; always checkpoint immediately after
#------------------------------------------------------------------------------
route_design
write_checkpoint -force ${OUTDIR}/post_route.dcp

#------------------------------------------------------------------------------
# 8. Post-Route Reports
#    Canonical AMD report set from UG892 §Non-Project Mode Tcl Script Example
#------------------------------------------------------------------------------
report_timing_summary    -file ${OUTDIR}/timing.rpt
report_timing            -sort_by group -max_paths 100 \
                         -path_type summary \
                         -file ${OUTDIR}/timing_paths.rpt
report_utilization       -file ${OUTDIR}/util.rpt
report_power             -file ${OUTDIR}/power.rpt
report_drc               -file ${OUTDIR}/drc.rpt
report_clock_utilization -file ${OUTDIR}/clk_util.rpt

#------------------------------------------------------------------------------
# 9. Outputs
#    write_debug_probes: only needed if ILA cores are present in the design
#    UG892 §Writing Design Output Files
#------------------------------------------------------------------------------
write_debug_probes -force ${OUTDIR}/debug.ltx
write_bitstream    -force ${OUTDIR}/${TOP}.bit

#------------------------------------------------------------------------------
# 10. Optional: export post-route netlist and constraints (for formal / ECO)
#     UG835: write_verilog, write_xdc
#------------------------------------------------------------------------------
# write_verilog  -force ${OUTDIR}/post_route_netlist.v
# write_xdc      -force ${OUTDIR}/post_route.xdc

puts "===== Build complete: ${OUTDIR}/${TOP}.bit ====="
```

## `run_sources.tcl` Template

Also generate this companion file template for the user to populate:

```tcl
#==============================================================================
# run_sources.tcl — User-maintained source file list
# Sourced by the main build script at the "Read Sources" stage.
# Add all RTL files, IP references, and XDC constraints here.
# Reference: UG892 (read_* commands), UG896 (IP usage), UG903 (XDC order)
#==============================================================================

# --- RTL Sources ---
# read_vhdl                    ../rtl/top.vhd
# read_vhdl    -library work   ../rtl/pkg.vhd
# read_verilog -sv             ../rtl/core.sv
# read_verilog                 ../rtl/utils.v

# --- IP Cores ---
# Always reference the .xci file, not the .dcp alone (UG896)
# read_ip  ../ip/clk_wiz/clk_wiz.xci
# read_ip  ../ip/fft/xfft.xci

# After reading all IPs, generate output products
# generate_target all [get_ips]

# --- Constraints ---
# User XDC files first, then IP-specific XDC (UG903: processing order)
# read_xdc  ../xdc/clocks.xdc
# read_xdc  ../xdc/pins.xdc
# read_xdc  ../xdc/timing_exceptions.xdc
```

## Clarifying Questions (ask if any are missing)

Before generating the script, confirm:

1. **Part number** — exact Xilinx part string (e.g., `xcvu9p-flgb2104-2-i`)
2. **Top-level module name** — the RTL entity to pass to `synth_design -top`
3. **Does the design include ILA / debug cores?** — to decide whether to include `write_debug_probes`
4. **Does the design include IP cores (.xci)?** — to remind about `generate_target all [get_ips]`
5. **Output directory preference** — default is `./out`

---

## Formatting Rules

- Always produce **two files**: the main build script and `run_sources.tcl`
- Every major stage (set_part, source, synth, opt, place, route, reports, outputs) must have
  a numbered comment header as shown above
- Inline `# Reference: UGxxx §Section` comments on every non-obvious command
- Use `${OUTDIR}/` consistently — never hardcode paths in the report/checkpoint commands
- `set_part` and `-part` in `synth_design` must both use the `$PART` variable
- Remind the user that `run_sources.tcl` is their responsibility to populate
- If the user's part number looks like an UltraScale+ or Versal device, add a note that
  `write_device_image` replaces `write_bitstream` for Versal devices
